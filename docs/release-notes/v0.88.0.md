## What's new in 0.88.0: Fix order sorts the whole list, not the author's

A big scenario lists its mods in whatever order its author typed them.
IslaMalvinasPVE, for example, brings 86 mods, and 108 of them sat ahead of a mod
they require. **Fix order** (and *Sort › Dependencies first*) used to move just
enough to fix that and keep the author's order everywhere else, so mod families
ended up far apart: `WCS_Armaments` at #9 and `WCS_SpaceCore`, built on it, at #48.

Fix order now rebuilds the list from the dependencies alone:

1. every mod comes after the mods it requires;
2. the frameworks other mods build on come first, the most-needed first;
3. everything else is sorted by name, so families such as `ARMA-RY …` or `FRS_…`
   sit together;
4. the scenario's own mod comes last.

The order the list was in before no longer matters: the same mods always come
back in the same order. Because this can rearrange an order you made by hand,
the note Fix order leaves has an **Undo** link that puts the previous order back.

The Guide's Mods section no longer mentions the AI mod sort, which v0.86.0 removed.

## Do I need to do anything?

No. Your saved templates keep their order until you press Fix order.

## Updating your setup files

No compose file, `.env` setting or script changed. Pull the new manager image:

- **Linux with the installer (`rsm`):** `sudo rsm update --all`.
- **Linux VPS:** the same.
- **Linux, installed by hand:** pull the new manager image and restart it.
- **Windows:** run `.\start.ps1`, which pulls the new manager image.
