## What's new in 0.62.1: the mod order you set is the mod order you keep

One bug fix.

## Do I need to do anything?

**No.** No `.env` or compose change, and no template, mod list or server is
touched by this.

## "Fix order" now survives a save

([#197](https://github.com/tubalainen/reforger-server-manager/issues/197))

Press **Fix order** on the Mods step, the list rearranges, press **Save
template** — and the next time you opened that template the old order was back,
warning banner and all. Dragging a mod into place or applying an AI order had the
same fate.

The order was in fact saved correctly every time: it was thrown away on the way
*back in*. Before the list became reorderable (0.50.0), the wizard always drew
mods as "your picks first, the dependencies they pull in after", whatever order
the array was stored in — and the code that reproduced that old layout was still
running every time a template was opened. Anything that put a dependency **above**
the mod that requires it — which is exactly what *Fix order* does — was undone on
sight.

Opening a template now shows the list exactly as it was saved, which is also
exactly the order that goes into `config.json`'s `mods[]`. Nothing re-sorts it
behind your back any more.

For a template you have never reordered, nothing changes: your picks are still
first and their dependencies still follow, because that is the order it was
stored in.

**Also:** the banner counted pairs, not mods, so one mod sitting above two of its
dependencies was reported as "2 mod(s) are listed before something they require".
It now counts the mods you would have to move.
