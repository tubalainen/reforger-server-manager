## What's new in 0.50.0 — mod load order, by hand or with an AI

The Mods step of a template is now a single list **in load order**: the order you
see is the order the mods are written to `config.json`. Drag any row to move it,
including the dependencies that were added for you
([#164](https://github.com/tubalainen/reforger-server-manager/issues/164)).

## Do I need to do anything?

**No.** Opening a template shows its mods in the order it has been running with,
and saving it untouched writes exactly the same `config.json` as before. Nothing
reorders itself — every change below is a button you press.

## Updating your setup files

*(Added after release — this is the paragraph the original notes should have
carried, and the reason [#167](https://github.com/tubalainen/reforger-server-manager/issues/167)
now makes the build fail when it is missing.)*

The one-click AI ordering below is configured through **three new `.env`
settings**. Your existing `.env` will not have them: it holds your password and
is never overwritten by an update. Everything in this release works without
them — the copy-and-paste route needs nothing configured — so add them only if
you want the one-click button:

```bash
AI_ORDER_URL=
AI_ORDER_MODEL=
AI_ORDER_KEY=
```

[`.env.example`](https://github.com/tubalainen/reforger-server-manager/blob/main/.env.example)
carries the same three with worked examples for Gemini, OpenRouter and a local
Ollama. The compose file did not change in this release.

## Drag a mod where you want it

The two separate lists — your picks, then "Dependencies · added automatically" —
are one list now, because a load order that cannot put a dependency first is not
really a load order. Dependencies still carry their badge and their "required by"
count, and still cannot be removed by hand; they can just be *moved*.

Each row shows its position, drag lifts it, and the ↑ ↓ buttons still work for
keyboard and touch. Above the list, a line says how many mods sit before something
they require, if any do.

**Dependencies first** is the deterministic version of that: it puts every mod
after the mods it requires and leaves everything else exactly where it is. It
needs no network and no AI, and it is a no-op when the list is already in order.

## AI order… — for the part a graph cannot decide

Dependencies are known facts. Whether *Extra Sounds* should load before or after
*Some Overhaul* is not — that is knowledge about what those mods actually do. So
there is now an **AI order…** button that asks a language model, and two ways to
reach one:

- **Copy the prompt** into ChatGPT, Gemini or Claude — all free, no account
  needed beyond the one you already have — and paste the answer back. This route
  needs nothing configured, and your mod list travels through your own browser
  rather than through your server.
- **One click**, if you put an OpenAI-compatible endpoint in `.env`
  (`AI_ORDER_URL`, `AI_ORDER_MODEL`, `AI_ORDER_KEY`). A free Google Gemini key, an
  OpenRouter `:free` model, or a local Ollama all work; `.env.example` has all
  three written out.

We looked for a free AI that could be called with no key at all, so the button
could just work for everyone. There isn't one any more: the anonymous endpoints
that used to offer this now either want payment for a fresh answer or have
retired their free tier. Hence the copy-and-paste route, which is free, needs no
account setup, and cannot break when somebody else changes their pricing.

### The answer is checked, not trusted

An AI answer is a *suggestion*, and it is treated like one. Before anything moves
you are shown how many mods change position, and:

- ids the answer invented that are not in your template are **ignored** and
  counted — nothing can be added this way;
- mods the answer forgot **stay where they already are** — nothing can be dropped
  this way;
- an id repeated later in the reply is not a second copy of the mod;
- by default the result is still nudged so every mod stays after what it requires,
  and it tells you when that happened. Untick the box if you want the answer
  verbatim.

The reply is read by pulling the mod ids out of it in order, so it does not matter
what shape the answer arrives in — a numbered list, a JSON array, a markdown
table, or the format the prompt asked for, with or without the model's usual
preamble.

The prompt itself contains mod ids, mod names, and which mod requires which.
Nothing about your server, its passwords or its players is in it, and no request
leaves the manager until you press a button.

## What we can and cannot tell you about load order

What is certain: the manager writes the mods to `config.json` in the order shown,
and the order is stable across saves.

What is not: whether the Reforger engine honours that order. Community guidance is
consistent — frameworks and libraries near the top, mods that patch or override
other mods at the bottom, since a later entry gets the last word — and the sources
that describe the array as the load order agree with each other. But there is no
statement from Bohemia we could find that confirms the engine reads it that way
rather than resolving dependencies itself. So this release gives you full control
of the order and honest guidance about it, and stops short of promising that
reordering fixes a broken server.

## Small print

- Mods files exported before this release are re-partitioned on import — picks
  first, dependencies after — so they land exactly where they used to. Files
  exported from this version keep the order you gave them.
- *Sort A–Z* and *Sort as added* now sort the whole list rather than only your own
  picks, since the list is one thing now.
