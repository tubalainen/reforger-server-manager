## What's new in 0.43.6

### Fix: a `$` in your username or password no longer breaks the login (#140)
Changing `ADMIN_USERNAME` (or picking a password) that contained a dollar sign
silently broke the GUI: the API returned *"not configured"* and the front end
threw errors, so it looked like nothing could reach the backend.

The cause was Docker Compose, not the app. Compose reads a single `$` in the
`.env` file as a variable reference and drops it, so `ADMIN_PASSWORD=abc$def`
reached the container as `abc`, and a value that *started* with `$` (for example
`ADMIN_USERNAME=$name`) arrived completely empty — which is what produced the
"not configured" error.

What changed:

- **`.env.example` now spells out the rule** right next to the credentials: a
  literal `$` must be written twice (`$$`), e.g. `ADMIN_PASSWORD=abc$$def` so the
  app sees `abc$def`. No other characters need escaping.
- **The Windows installer escapes it for you.** If the password you type into the
  installer contains a `$`, it is now written to `.env` correctly, so the
  double-click setup works with any password.
- **Clearer diagnostics.** When a credential arrives empty, the login error and a
  startup log line now say exactly what happened and how to fix it, instead of a
  bare "not configured".

If you already hit this, add the missing `$` back as `$$` in your `.env` and
restart — no reinstall needed.

**Upgrade:** the manager updates itself on start, or pull
`ghcr.io/tubalainen/reforger-server-manager:latest`.
