## What's new in 0.93.0: The failing-mods box names the mod whose script does not compile

After a game update, a mod's scripts may no longer compile, and the server
then does not start. Until now the red box on the server page said only *a
mod's scripts did not compile. The log does not say which mod.*

### The mod is now named

The server's log gives the script that failed, for example
`scripts/Game/Player/RO_V_PlayerController.c`, but not the mod it came from.
The manager now looks that file up in the mod folders on the server's disk:
each mod's `.pak` lists the files it holds.

The box then reads, for example:

> The last start failed: Realism Overhaul - Vehicles has a script that does
> not compile.
> Its script scripts/Game/Player/RO_V_PlayerController.c (line 24) does not
> compile: Undefined function '…'. It is probably not updated for this game
> version.

**Remove in template…** marks that mod in the template editor, as it does for
a mod with a missing dependency.

Only the error the engine stopped on blames a mod. Later errors in the same
log may follow from the first, so they are listed under *Script compile
errors* with the mod that ships each file, but they do not mark a mod as
failing.

### When no mod folder holds the file

The file can be the base game's own (a mod changed something it relies on),
or the mod folders can be gone. The box then shows the errors as before. If
an AI service is set up in `.env` and answering, it also shows an **Ask AI**
button, which asks about that log file the same way the Console's button
does. The AI's answer is a lead: it never marks a mod as failing.

### How far this was checked

The `.pak` layout was taken from an open-source reader. The header and the
end of the file list of one real mod's `data.pak` match it. The box itself
has not yet been seen on a real server with a failing mod. If a `.pak` is
laid out differently, the box falls back to searching the file's name in the
pak, and failing that to the message above.

## Do I need to do anything?

No.

## Updating your setup files

No compose file, `.env` setting or script changed. Pull the new manager image:

- **Linux with the installer (`rsm`):** `sudo rsm update --all`.
- **Linux VPS:** the same.
- **Linux, installed by hand:** pull the new manager image and restart it.
- **Windows:** run `.\start.ps1`, which pulls the new manager image.
