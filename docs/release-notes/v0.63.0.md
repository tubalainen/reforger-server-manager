## What's new in 0.63.0: ask a local Ollama for the mod load order

The template wizard's **Sort › Order with an AI…** can now answer in one click
from an [Ollama](https://ollama.com) running on your own machine: free, no API
key, and the mod list never leaves the host. It's a small model that fits a
**4 GB** graphics card
([#199](https://github.com/tubalainen/reforger-server-manager/issues/199)).

## Do I need to do anything?

**No.** Nothing changes unless you want to use Ollama. The copy-and-paste route
keeps working as before, and so does an existing `AI_ORDER_URL` that points at
Gemini, OpenRouter or any other OpenAI-compatible service.

## Updating your setup files

Only if you want to use Ollama. The compose files gained an optional `ollama`
service, and pulling the image doesn't update them, so download the compose
file for your install type again (or copy the new `ollama:` service and the
`reforger-ai` network from
[docker-compose.yaml](https://github.com/tubalainen/reforger-server-manager/blob/main/docker-compose.yaml)).
Follow
[Updating your setup files](https://github.com/tubalainen/reforger-server-manager#updating-your-setup-files)
for your install type. The service starts only when you turn it on. Then add
these lines to your `.env`:

```bash
COMPOSE_PROFILES=ollama
AI_ORDER_URL=http://ollama:11434
AI_ORDER_MODEL=qwen2.5:3b
```

Start the stack again and download the model once:

```bash
docker compose up -d
docker exec reforger-ollama ollama pull qwen2.5:3b
```

(On Windows, use `docker-compose.windows.yaml` / the start shortcut, and the
same `docker exec` line.) The service uses an NVIDIA GPU. On Linux that needs
the [NVIDIA Container Toolkit](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/);
Docker Desktop on Windows needs nothing extra. No NVIDIA GPU? Delete the
service's `deploy:` block and it runs on the CPU, slowly.

The Linux `docker-compose.yaml` also gained `extra_hosts:
host.docker.internal:host-gateway`, so a manager on Linux can reach an Ollama
installed directly on the host (`AI_ORDER_URL=http://host.docker.internal:11434`;
start Ollama with `OLLAMA_HOST=0.0.0.0` and keep port 11434 firewalled).

## Which model for a 4 GB GPU

**`qwen2.5:3b`.** It's also what the manager uses when `AI_ORDER_MODEL` is
empty and the URL points at Ollama.

Measured on a real Ollama (0.34.2) before this release:

| Mods in the list | Context the manager asked for | GPU memory used | Answer time |
|---|---|---|---|
| 45 | 5k tokens | 2.1 GB | ~13 s warm, ~70 s the first time |
| 150 | 14k tokens | 2.5 GB | ~70 s |

It returned all 45 ids in the 45-mod run and 147 of 150 in the 150-mod run.
The wizard already copes with a small model's slips: a forgotten mod keeps its
place, a mis-copied id is ignored, and dependency order is repaired unless you
untick it. Nothing is applied until you've seen what would move.

Alternatives: `llama3.2:3b` also fits in 4 GB; with 8 GB or more, `qwen2.5:7b`
orders better. Avoid "thinking" models (`qwen3`, `deepseek-r1`) on a small card:
they reason for minutes before they answer. If one is used anyway, its
`<think>` section is now removed before the answer is read, so the ids it
mulls over can't scramble the order.

## Why Ollama needed more than "it's OpenAI-compatible"

0.50.0 already suggested pointing `AI_ORDER_URL` at Ollama's
`/v1/chat/completions`. That route can't be told how big a context window to
use, and Ollama's default is 2–4k tokens. A 45-mod prompt alone is ~2k tokens,
and Ollama doesn't refuse a longer one: it silently drops the **start**, which
is the instructions. So the model answered a question it never saw.

The manager now spots Ollama from the URL (a bare `http://host:11434`, a URL
ending in `/api/chat`, or the old `/v1/chat/completions` on port 11434) and
talks to its own `/api/chat` instead. It sizes the context window for each
request to fit the prompt plus the answer (4k–32k tokens), caps the answer
length, and waits up to 5 minutes rather than 90 seconds, because a small card
first has to load the model. Two setup mistakes now come with their fix in the
error message: a model that hasn't been pulled yet (it names the exact
`ollama pull` command), and an Ollama that can't be reached (it names
`OLLAMA_HOST`).

## Small print

- The wizard's button now says what it will ask, such as
  **Ask Ollama (qwen2.5:3b)**, and warns that a local model can take a minute.
- The Ollama service is on its own `reforger-ai` network, shared only with the
  manager. The game servers, which run untrusted Workshop mods, can't reach it,
  and it publishes no port.
- Behind nginx, a request can outlast the default 60-second
  `proxy_read_timeout`. Raise it if the button fails with a 504. Caddy (the VPS
  setup) has no such limit.
- The VPS compose file is unchanged: point `AI_ORDER_URL` at an Ollama elsewhere
  if you want one there.
