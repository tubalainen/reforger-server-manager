## What's new in 0.48.0 — the save row tells the truth

On a server instance, **Stored data** reported the save game as *empty* even when
there was one on disk, and the row said nothing about the persistence settings
that produced it
([#160](https://github.com/tubalainen/reforger-server-manager/issues/160)).

## Do I need to do anything?

**No.** Nothing about how servers run or save changed — this is what the manager
*reports*, and the clear button acts on what the row now correctly finds.

---

## Why it said empty

The scan looked for the save in exactly one place: the top level of the
instance's `profile/` directory. The engine does not commit to that. Depending on
the build the save tree sits at `profile/.save/…` or a level deeper, and a
scenario's own persistence storage can put its database somewhere else again — so
one extra level of nesting was enough to report a perfectly good save as nothing
at all. That is the row people check *before* wiping something.

It now searches the whole profile directory, stops at the first save it finds
(so you see `profile/.save`, not its hundreds of save points), and skips the log
and addon trees so nothing is counted under two headings. The row also prints
**where** it found the files, relative to the instance directory, instead of just
the folder name — that is the path to copy when backing the world up.

## The row is now tied to the persistence settings

It is renamed from *Saved game data* to **Persistence (save games)**, matching the
template wizard's section of the same name, and it says which template's settings
wrote it:

> **Persistence (save games)** `5 KB` `destructive`
> `profile/.save` · 2 file(s)
> *template "Conflict Everon" configures persistence (hive id 7).*

When there is no save, it says why there might not be, rather than leaving
*empty* to look like a broken readout:

> *template "Conflict Everon" does not configure persistence, so the server uses
> the engine's own defaults — which still save. Nothing has been saved yet: not
> every scenario writes a save (Game Master, for one, does not).*

**Upgrade:** the manager updates itself on start, or pull
`ghcr.io/tubalainen/reforger-server-manager:latest`.
