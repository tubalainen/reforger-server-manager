## What's new in 0.47.0 — the complete persistence settings

The template's **Persistence (save games)** section only ever wrote two of the
server's persistence options. The other three were missing from the wizard *and*
from the rendered `config.json`, so however you set the template up, your server
silently ran on the engine defaults for them
([#156](https://github.com/tubalainen/reforger-server-manager/issues/156)).

All five are now there.

## Do I need to do anything?

**No.** Existing templates keep the auto-save interval and hive id they already
had, and the three new values start at the engine's own defaults — the same
behaviour your server has been running with. Change them only if you want to.

---

## The settings, and what each one does

| Setting | Range / default | What it does |
|---|---|---|
| Auto-save interval (min) | 0–60, default 10 | How often an automatic save is created. **0 turns automatic saves off.** |
| **Save points kept** | 1–128, default 10 | How many save points are retained for the mission. **New.** |
| **Load the latest save on startup** | default on | Whether the server resumes from the newest save point when it starts. **New.** |
| **Keep save points after the mission ends** | default off | Whether a playthrough's saves survive the end of the mission. **New.** |
| Hive ID | 0–16383, default 0 | Separates save data when several servers share one persistence database. |

Each field now carries a one-line explanation under it, and every change lands in
the template's change log by name, e.g.
*`game.gameProperties.persistence.saveRetention: 10 → 20`*.

## "Enable persistence" is now "Configure persistence"

The old label promised something the checkbox could not deliver. **The Reforger
server saves on its own by default** — the `persistence` block is optional, and
leaving it out does not switch saving off. So:

- **Ticked** — the manager writes a `persistence` block with the values above.
- **Unticked** — no block is written and the engine decides. Saving still happens.

To stop a scenario saving at all you have to disable the save types on the mission
header, which is a scenario-level setting rather than a persistence one. Use
**Edit JSON** and add, under `game.gameProperties`:

```json
"missionHeader": { "m_eSaveTypes": 0 }
```

The wizard says all of this in place, and there's a new entry in the User Guide.

---

## Also in this release

- A template saved by an older version — with only `autoSaveInterval` and `hiveId`
  in its persistence block — opens with the three new fields on their documented
  defaults, and none of them is mistaken for a hand-edited custom key.
- `databases` and `storages` are still written as empty objects. They are
  free-form named overrides with no GUI equivalent; a custom one added through
  **Edit JSON** is preserved as before.

Field names, ranges and defaults follow Bohemia's
[Server Config](https://community.bistudio.com/wiki/Arma_Reforger:Server_Config#persistence)
documentation for 1.6.0.

**Upgrade:** the manager updates itself on start, or pull
`ghcr.io/tubalainen/reforger-server-manager:latest`.
