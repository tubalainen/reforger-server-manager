## What's new in 0.55.1 — Nobody else's data, nobody else's name

Two small things that were quietly wrong.

## Do I need to do anything?

**No.** No `.env` or compose change, and nothing about existing servers, templates
or backups changes.

## A new server can no longer inherit a deleted one's world

([#187](https://github.com/tubalainen/reforger-server-manager/issues/187))

Instance ids are SQLite rowids, and SQLite hands the highest one straight back
out after a delete:

```
created:             a=1, b=2
after delete+create: a=1, c=2
```

Deleting an instance **without** ticking *also delete stored data* leaves
`data/instances/<id>/` on disk — that is deliberate, and the dialog says so. But
the next instance created could then be given that id, and instance creation
never looked at the disk. The new server silently adopted the dead one's profile,
the world in it, its mod bake and — since 0.54.0 — its entire **backup shelf**,
shown under a new name on a server that never wrote a byte of it.

Now, when a new instance is handed an id that still has data on disk, that data
is **moved aside** to `data/orphaned-instances/<id>-<timestamp>/` and the new
server starts empty. Nothing is deleted: a rename keeps every file, including
root-owned ones, and the GUI says where it went:

> This server was given an id that a deleted server had used, and that server's
> stored data — its world and its backups — was still on disk. It has been moved
> to `…/orphaned-instances/2-20260906-124500` rather than handed to the new
> server, which starts empty. Nothing was deleted.

If the move cannot happen at all, the instance is not created and the message
names the folder — adopting someone else's world is the failure this exists to
prevent, so it is never the fallback.

The parked copy sits outside `instances/`, so the log-retention sweep and
everything else that walks live servers leave it alone. Delete it yourself when
you are sure you do not want it.

**Also:** a backup's metadata file whose archive is gone was invisible to the
listing and never cleaned up. Opening the backups card now tidies those away.

## New templates get a name of their own

([#186](https://github.com/tubalainen/reforger-server-manager/issues/186))

Every new template started life as `Arma Reforger Server`, so that is what the
in-game browser filled up with — one prefilled field nobody edited, multiplied by
everyone.

A new template now starts as, for example, **Arma Reforger Server Hidden Ridge**:
the same prefix people search for, plus two words of its own. Type over it with
anything you like, or press **🎲 Randomize** for another suggestion — it is only
a starting value, and the field is where it always was, on the Settings step.

Editing an existing template still loads its saved name, so nothing is ever
renamed behind your back.
