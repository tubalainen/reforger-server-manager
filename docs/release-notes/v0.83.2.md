## What's new in 0.83.2: `rsm update` says which version you got

`sudo rsm update` and `sudo rsm update --all` now print the version each team's
manager runs before and after the update, with a link to that release's notes:

```
== stack kompaniet
Updating stack 'kompaniet' (now on v0.83.1)...
...
Stack 'kompaniet': v0.83.1 -> v0.83.2
  What's new: https://github.com/tubalainen/reforger-server-manager/releases/tag/v0.83.2
```

When there was nothing newer, it says so: `Stack 'kompaniet': already on v0.83.2.`
It also says if `MANAGER_VERSION` in `.env` pins the version. `rsm supervisor update`,
and the Supervisor's part of `rsm update --all`, report the same way.

## Do I need to do anything?

No.

## Updating your setup files

Only the `rsm` command changed. It replaces itself at the end of every
`rsm update`, so:

- **Linux with the installer (`rsm`):** run `sudo rsm update --all` as usual.
  That run still uses the old `rsm` and prints no versions; it installs the new
  `rsm`, and every update after it prints them. Run it a second time if you
  want to see the line right away.
- **Linux VPS:** the same.
- **Linux, installed by hand:** pull the new manager image and restart it. You
  have no `rsm`, so nothing else changes.
- **Windows:** run `.\start.ps1`, which pulls the new manager image.
