## What's new in 0.87.0: see the order the engine really loaded your mods in

Part of [#257](https://github.com/tubalainen/reforger-server-manager/issues/257).

Until now nobody could say whether the server follows the order of the mods in
`config.json`. The engine does say, in each server's own `console.log`: right
before it loads the world, it mounts the mods one by one
(`FileSystem: Adding package …`), with the base game last.

A server's **Settings › Mods** card now has a **Load order the engine used at the
last start** section. It reads that order from the server's latest session log and
shows it next to each mod's place in the `config.json` that start was given. A
one-line summary says whether the engine followed your list, reversed it, or
reordered it. It also counts the mods the engine loaded that aren't in your list:
dependencies the server fetched itself.

The first log checked this way (a public server log, compared with the config it
started with) was revealing. The engine mounted the list **in reverse**, and
**moved each mod ahead of the mods it depends on by itself**. If your servers
show the same, the engine settles dependency order on its own. In that case
your ordering decides only between mods that don't depend on each other, and
Fix order is a tidy list rather than a requirement. Open the section on a
server that has started once to check.

## Do I need to do anything?

No. The section reads what is already on disk; a server needs to have started once.

## Updating your setup files

No compose file, `.env` setting or script changed. Pull the new manager image:

- **Linux with the installer (`rsm`):** `sudo rsm update --all`.
- **Linux VPS:** the same.
- **Linux, installed by hand:** pull the new manager image and restart it.
- **Windows:** run `.\start.ps1`, which pulls the new manager image.
