## 0.81.2: file names stay file names when saves are cleared or restored

A security fix found in the security review of 2026-10-20
([docs/security-review.md](https://github.com/tubalainen/reforger-server-manager/blob/main/docs/security-review.md),
F3).

The game server writes its files as root, so the manager uses a short-lived helper
container to clear stored data and to restore a save backup. That helper was given one
command line with the paths written into it. Those paths are whatever is on disk in the
server's profile. A Workshop mod chooses the names of the files it writes there, and an
uploaded backup chooses the names inside it. A name containing a quote could end the
command early and run a command of its own, as root inside the helper container.

The helper now runs a fixed command and receives the paths as separate arguments, so a
name can only ever be a name. An uploaded backup with a line break or another control
character in a file name is refused.

## Do I need to do anything?

**Update the image.** Nothing else changes: the compose files and `.env` are the same, and
so is what **Clear data** and **Restore** do.

```bash
sudo rsm update --all
```

On Windows, run the Start shortcut as usual; it pulls the new image.

## Small print

- The Docker gate kept the helper container away from the host: it mounts only that one
  server's folder. A malicious mod could still have turned its own data into a program run
  with a network connection, which is what this closes.
- Tests run both helper scripts through a real shell with a file named
  `x'; touch pwned; '` and check that the file is removed and nothing else happens.
