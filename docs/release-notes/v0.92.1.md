## What's new in 0.92.1: The failing-mods box, checked against a real server

The red box from 0.92.0 names the mods that stopped a server's last start.
On a real server, three things in it were wrong or missing.

### It names the template mods that bring in a failing mod

A server fetches a mod's dependencies by itself, so the mod that fails is
often in no template at all. One real case: WCS_Scopes, which a template mod
needs, updated to 9.0.2. That version needs WCS_NATO and WCS_RU, and the
server never downloaded them.

The box used to say only *not in the template*. It now names the template
mods that bring the failing mod in, for example *Not in your template:
Escapists RHS Customize faction brings it in.* It works this out from each
mod's project file on disk.

Those template mods are marked *needs a failed mod* in the template editor
and under Settings › Mods, so you can see what to remove.

### Mods are matched by the name the engine uses

The engine logs a mod under its project name, which can differ from its
folder's name. For example, the folder `EscapistsRHS_Customize_faction` holds
the project `EscapistsWCSFORTEXCustomize`. That mod went unrecognised before;
it is now matched through its project file.

### Fixed: the base game listed as a missing dependency

Most mods depend on the base game (`58D0FB3206B6F859`). The base game is
never in the Workshop folder, so 0.92.0 listed it as a dependency that
*isn't installed*. Anything the server's log lists as available, the base
game included, now counts as installed.

## Do I need to do anything?

No.

## Updating your setup files

No compose file, `.env` setting or script changed. Pull the new manager image:

- **Linux with the installer (`rsm`):** `sudo rsm update --all`.
- **Linux VPS:** the same.
- **Linux, installed by hand:** pull the new manager image and restart it.
- **Windows:** run `.\start.ps1`, which pulls the new manager image.
