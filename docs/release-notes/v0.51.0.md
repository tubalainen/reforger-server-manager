## What's new in 0.51.0 — mod templates: save a mod set once, reuse it everywhere

There is a new **Mod Templates** page. A mod template is a saved list of mods and
nothing else — no scenario, no server settings — that you can load into the Mods
step of any server template
([#166](https://github.com/tubalainen/reforger-server-manager/issues/166)).

If you run several servers off the same pack of mods, this is the thing that was
missing: build the set once, keep it named and versioned in one place, and load
it wherever you need it.

## Do I need to do anything?

**No.** Nothing about your existing templates, instances or mods changes. The new
page starts empty, and a server template only ever changes when you load a mod
template into it and press Save.

---

## Building a mod template

Mod Templates → **+ New mod template**. Adding mods works exactly as it does in
the wizard: search the Workshop, or paste ids and Workshop URLs — several at once,
comma-separated. Each mod follows the latest Workshop release unless you lock a
version, and the list is **in order**: drag a row, or use ↑ ↓.

Every mod is a plain top-level addon, like adding one mod in the wizard: a
Reforger server downloads a mod's own dependencies itself, so a mod template lists
what you chose and nothing you didn't.

## Loading one into a server template

Open a template's **Mods** step and press **🧰 Mod template…**. Pick a list, then
pick what should happen:

- **Add to this template** — the mods already there stay exactly where they are,
  and the rest are appended in the mod template's order.
- **Replace the mod list** — the template ends up with exactly that list, in its
  order. The scenario's own mod (and whatever it requires) always stays: a server
  runs its scenario, and no mod list may quietly take that away.

Either way you are shown what it would do first — how many mods would be added,
how many removed, and how many would take the mod template's version lock — with
the resulting order listed underneath. Nothing moves until you press *Load these
mods*, and nothing is written to `config.json` until you save the template.

**A load is a copy, not a link.** The server template keeps its own mods, so
editing or deleting a mod template later cannot change a server you have already
built. When you want the newer set, load it again.

## Every change is recorded

Like server templates since 0.39, each mod template keeps its own searchable,
read-only change log: mods added and removed, version locks changed, renames, and
reorderings ("Load order changed — 3 mod(s) moved: …"). It cannot be edited or
deleted, and it goes only when the mod template does. Both logs are now the same
piece of code, so they read and search identically.

## The Mods Overview counts them too

A mod you have put on a mod template is **in use**, even if no server template
lists it yet: it appears in the Mods Overview with a 🧰 badge naming the mod
template it sits on, it is not marked *unused*, and **Clear & rescan** will not
prune it. Delete the mod template and its mods become prunable again, as you would
expect.

## Small print

- Mod template names are unique, and a mod listed twice in one is stored once —
  a repeat is not a load-order instruction the engine could act on.
- Version locks travel with the list. Loading a mod template over a mod you had
  locked to a different version re-locks it to the mod template's choice, and the
  preview counts that before you commit to it.
- Deleting a mod template asks first, and says plainly that server templates built
  from it keep their mods.
