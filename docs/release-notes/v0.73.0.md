## What's new in 0.73.0: run a server on an older Prod version

Since 0.72.0 every release of a Prod template is a version (v1, v2, …). Now a
server can stay on one of them (#223).

- **A server's Settings tab** shows a version picker under a Prod template.
  **Latest** is the default: the server follows every new release on its next
  restart, as before. Pick **v1**, **v2**, … to keep it on exactly that release
  until you change it. Each version shows when it was released and its release
  note.
- **New server** offers the same choice, and starts with a Prod template
  selected.
- **Templates are grouped** Prod, Dev, Test in both template pickers.
- A pinned server never shows *template changed*, because what it runs never
  changes. The servers list and the server page show the version it really
  runs, such as **Prod v1**.
- **+ New template › Based on a Prod template…** can start from an older
  version, not only the latest. So can **+ New mod list › Based on a Prod mod
  list…**.
- **From a mod list…** in a template's Mods step lists the mod lists by stage,
  and can load an older version of a Prod list.
- A Prod template's ⋯ menu downloads the latest config.json. An older one is at
  `/api/templates/<id>/config.json?version=<n>`.

### The Server Supervisor shows the version

A server on a Prod template now carries the version in its name for the
Supervisor, such as "Conflict Everon v2". Each such server's container is
rebuilt once, on its next start, to pick up the new name. That takes a few
seconds; its saved game, mods and logs are untouched.

## Do I need to do anything?

**No `.env` or compose change.** Update as usual. On Linux:

```bash
sudo rsm update
```

On Windows, run the start shortcut as usual; it pulls the new image.

Every existing server keeps running the latest version of its template.
