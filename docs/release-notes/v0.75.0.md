## What's new in 0.75.0: several teams on one VPS, each at its own domain

Since v0.65.0 a machine can run several teams' installs (*stacks*). On a VPS
only one of them could be on the web, though: its own Caddy holds ports 80 and
443, and every other stack's GUI was reachable only through an SSH tunnel. This
release adds the last part of
[#204](https://github.com/tubalainen/reforger-server-manager/issues/204): one
shared HTTPS front, the **edge**, for every team on the machine.

- **A domain per team.** `sudo rsm add-stack team2 --domain team2.example.com`
  sets up a second team on a VPS with its GUI at `https://team2.example.com`.
  The edge gets and renews every certificate. Each team still has only its own
  login, servers and data.
- **Your current install moves behind it on its own.** The first time, the
  edge takes ports 80 and 443 over from the stack that has them, at the domain
  it already uses. That stack's own Caddy is switched off; nothing else about
  it changes.
- **The teams still share nothing.** The edge reaches each manager over that
  stack's own network. One team's containers cannot reach another team's
  manager, nor the edge's controls. Each manager believes the client address
  the edge passes on from that network only, so login throttling sees every
  real visitor.
- **The Server Supervisor too, if you like.**
  `sudo rsm edge add --supervisor ops.example.com` puts its page on HTTPS.
  It then refuses to start on a weak password, like anything on the internet.
- **All of it from `rsm edge`:** `rsm edge` (what it serves), `add`, `remove`,
  `logs`, `update`, `restart` and `uninstall`. `sudo rsm update --all` updates
  it with the stacks and the Supervisor. See
  [Several teams on a VPS](https://github.com/tubalainen/reforger-server-manager/blob/main/docs/installation.md#several-teams-on-a-vps-the-shared-edge).

## Do I need to do anything?

**No.** Nothing changes for an install until you run `rsm edge add` or
`rsm add-stack --domain`. A single VPS install keeps its own Caddy.

## Updating your setup files

Only `rsm` itself changed for existing installs. `sudo rsm update` updates it
at the end, and the edge commands work from the next run. No compose file you
already have changed, and `.env` has no new setting (`.env.example` only gained
a comment).

There are three new files. `rsm` downloads each one when it is needed:

- `docker-compose.edge.yaml` is the edge itself, in `/opt/rsm-edge`.
- `docker-compose.vps.behind-edge.yaml` goes next to a stack's
  `docker-compose.vps.yaml` once the edge serves it, and switches that stack's
  own Caddy off. By hand:
  `docker compose -f docker-compose.vps.yaml -f docker-compose.vps.behind-edge.yaml up -d`.
- `docker-compose.supervisor.behind-edge.yaml` does the same for the
  Supervisor, with `docker-compose.supervisor.yaml`.

`rsm` writes `PROXY_SUBNET` into the `.env` of each stack it serves through
the edge, except the first stack, which keeps the default. The setting has been
in the VPS compose file since v0.44.0. It now gives each stack's proxy network
a subnet of its own.

- **Linux with the installer (`rsm`):** `sudo rsm update`, then
  `sudo rsm add-stack NAME --domain DOMAIN` or `sudo rsm edge add STACK DOMAIN`.
- **Linux VPS:** the same.
- **Linux, installed by hand:** use `rsm` for the edge. Or follow the
  [by-hand notes](https://github.com/tubalainen/reforger-server-manager/blob/main/docs/installation.md#several-teams-on-a-vps-the-shared-edge).
- **Windows:** nothing; the edge is for Linux VPS machines.

## Small print

- Every stack served by the edge runs the VPS compose file. A stack set up
  with the plain `docker-compose.yaml` (on a VPS, one added without a domain)
  is moved to it when it is first served. It keeps its containers and data,
  but its GUI port closes, since the edge is then the only way in. Its manager
  restarts once, which stops its game servers; auto-start ones come back.
- `rsm edge uninstall` works with at most one stack left on the edge, which
  then gets its own Caddy back. Two stacks cannot both hold ports 80 and 443.
- A stack taken off the edge with `rsm edge remove` keeps its own Caddy off,
  so its GUI is out of reach until it is served again.
- The edge issues its own certificates. Each one is requested once, when a
  domain moves to it.
- Plain HTTP (`http://name.example.com`) works for tests. The login then
  crosses the network unencrypted.
