## What's fixed in 0.96.1: Kick and ban reach the server on Linux

0.96.0 added **Kick**, **Ban…** and the ban list to the Players tab, over the
server's RCON. On a Linux install, where game servers use host networking, the
manager could not reach that RCON at all: every action ended in *No answer
from RCON*.

The manager sent to `host.docker.internal`, which the compose file maps to
Docker's default bridge. Docker drops traffic from the manager's own network to
that bridge's address. It now sends to the host's address on its own network
(its default gateway), which answers. Found on Docker 29 with a live Arma
Reforger 1.9 server: the old address got no answer, the new one logged in and
answered `#players` at once.

Docker Desktop (Windows) was not affected: there the manager reaches the
server by its container name.

Also: the Linux installers' last line now points to **System › Server files**
for the first download, not the old *Server Instances* page.

## Do I need to do anything?

No.

## Updating your setup files

No compose file or `.env` setting changed. The installer scripts changed only
in the text they print. Pull the new manager image:

- **Linux with the installer (`rsm`):** `sudo rsm update --all`.
- **Linux VPS:** the same.
- **Linux, installed by hand:** pull the new manager image and restart it.
- **Windows:** run `.\start.ps1`, which pulls the new manager image.
