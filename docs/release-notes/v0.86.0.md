## What's new in 0.86.0: Ask AI on log files, and the AI mod sort is gone

Follow-up to [#254](https://github.com/tubalainen/reforger-server-manager/issues/254).

### Ask AI on log files

The **Log & crash files** list in a server's Console now has an **✨ Ask AI**
button on each text log (`error.log`, `console.log`, `script.log` …; crash dumps are
binary and get none). It shows only while the AI service in `.env` answers, like the
button on the Console's error lines.

A whole log file is pruned before it is sent. A real `error.log` ran to 1,380 lines
(about 70,000 tokens), and 721 of them were errors of only a few dozen kinds, the
same handful repeated hundreds of times. The manager sends each distinct error once,
**with how many times it occurred**, plus the file's last lines. That cut the question to
about 2,300 tokens, 97 % less, which matters on a small GPU. The AI is asked which
errors actually break something for the players, which are noise, and what to do
about the ones that matter. The dialog says how the file was boiled down.

### Better answers

Both questions (an error line, a log file) were tuned against a real local model:

- **Plain text.** Answers come without Markdown marks.
- **Advice fits this manager.** The AI is told how the server is run here, so it says
  "change the port in the server's Settings" or "add the mod to the server template",
  not "edit your startup script".
- **No guessing.** It names a mod only when the log line names it, and no longer
  blames the many harmless "Wrong GUID/name for resource" lines on a broken
  download.

### Thinking models on Ollama work

A model that "thinks" before it answers spent its whole answer budget thinking and
came back empty: "The AI service returned an empty answer." The manager now asks
Ollama what the model can do. If it thinks, the manager tells it to answer directly,
which needs Ollama 0.9 or later. If an answer is still empty, the message says why.

### The AI mod sort is removed

**Sort › ✨ Order with an AI…** in the template wizard is gone. Its one guaranteed
benefit, every mod after the mods it requires, is exactly what the built-in **Fix order**
(and **Sort › Dependencies first**) does: instantly, the same way every time, with no
AI. Nothing showed that the extra ordering by mod names (frameworks first, patches
last) changes how the server loads. **Fix order**, the other Sort options and
drag-and-drop are unchanged.

## Do I need to do anything?

No. The `AI_ORDER_URL`, `AI_ORDER_MODEL` and `AI_ORDER_KEY` settings keep their
names and now serve **Ask AI** only.

## Updating your setup files

`.env.example` and the compose files changed, but only their comments: there is no
new setting. Your `.env` and compose file need nothing.

- **Linux with the installer (`rsm`):** `sudo rsm update --all`.
- **Linux VPS:** the same.
- **Linux, installed by hand:** pull the new manager image and restart it.
- **Windows:** run `.\start.ps1`, which pulls the new manager image.
