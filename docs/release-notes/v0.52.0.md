## What's new in 0.52.0 — Backup &amp; restore

Everything you have built in the manager — every **server template** and every
**mod template** — now goes into one file you can keep somewhere safe, carry to
another machine, or restore after a rebuild
([#173](https://github.com/tubalainen/reforger-server-manager/issues/173)).

There is a new **Backup** tab in the top navigation.

## Export

One click downloads the whole shelf as a single `.json` file. Each server
template travels complete: its scenario, its mods in their load order with the
version locks, every setting, the engine launch parameters, and any custom
config keys you added by hand in *Edit JSON*. Mod templates come along whole
too.

**Treat the file as a secret.** It contains the server, admin and RCON passwords
in clear text. That is deliberate — a backup that quietly blanked the admin
password would restore an unprotected server — so keep it where you would keep
the passwords themselves.

Server *instances* are not in the file. A running server is a container, a port
lease and a folder of saved games belonging to one host; none of that travels.
Your templates are what you built, and they are what comes back.

## Import — you see what it would do before it does it

Pick a backup file and nothing is written yet. You get a list of everything in
it, each template marked:

- **New** — not on this manager, so it can simply be imported.
- **Already here** — identical to what you have; nothing to do.
- **Differs** — same name, different content. The row then lists **exactly what
  differs**, in the same words the change log uses: *"game.maxPlayers: 100 →
  32"*, *"Added mod 'Extra Sounds'"*, *"Launch parameter max_fps: 120 → 60"*.
  Passwords are reported as *changed*, never printed.

For each differing template you choose:

- **Keep what I have** — leave your version alone.
- **Overwrite with the file** — put the backup's version back. The template
  stays in place, so servers built from it follow the restored settings the next
  time they start.
- **Import as a copy** — the file's version lands beside yours as
  *"name (imported)"*, so you can compare the two and delete one later.

**Restore everything** and **Only what's missing** set every row in one go, and
you can still change any individual row afterwards.

## The rules it follows

- **All or nothing.** If any part of an import can't be applied, none of it is —
  there is no half-restored shelf to clean up.
- **Nothing is imported unasked.** A template you didn't decide about is left
  alone, and a name that already exists is never overwritten by default.
- **It writes history.** An imported template opens its change log saying it came
  from a backup; an overwrite is recorded as the edit it is, so a server's
  settings never change shape without a trace.
- **It respects edit locks.** A template open in the wizard in another session
  can't be overwritten under them.
- Imported mods join the **Mods Overview** like any other save, so a restored
  template's mods are immediately in use there.

## Small print

- The file is plain, readable JSON with a `format` tag. A backup from a newer
  manager than yours is refused with a message rather than half-read, and a file
  that isn't a backup says so instead of failing obscurely.
- Templates saved before the manager kept a detailed mod list export their mods
  from their `config.json`, so an old template still restores with a usable mod
  list.
