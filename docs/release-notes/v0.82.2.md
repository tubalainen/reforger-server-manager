## What's fixed in 0.82.2

Follow-up to [#246](https://github.com/tubalainen/reforger-server-manager/issues/246).

- **The mod download bar is right when mods are updated.** It used to compare
  everything on disk with the Workshop's size for the whole template. An update
  starts with nearly all of that on disk, and mods take more room on disk than
  the Workshop says, so the bar read "20.45 GB of 19.28 GB · 100 %" while still
  downloading. Now each start counts only what it has to fetch: the mods that
  are missing, or on disk at another version than the one this start asked for.
  - An update reads "Updating 2 mods: 1 of 2 done", with the mods' names.
  - A first download reads "Downloading mods: x of y", per mod.
  - A start with nothing to fetch says "Mods up to date".
- **The Console follows the server again after a restart.** It reconnected a
  fixed moment after Start, which a slower start (one that first looks up every
  mod's newest version) could beat, leaving "No container yet — start the
  server." on screen for good. A restart from Force update never reconnected at
  all. The Console now reconnects as soon as the server is running again, and
  a crashed server's last lines stay on screen until then.
- **A stopped server is not restarted by a daily restart it missed.** A stopped
  server skips its daily restart, as before. But starting it within an hour of
  the skipped time got it restarted about 15 seconds later, which also updated
  its mods when mod updates were on. The skipped time now counts as handled.

## Do I need to do anything?

No.

## Updating your setup files

No compose file, `.env` setting or script changed. Pull the new manager image:

- **Linux with the installer (`rsm`):** `sudo rsm update --all`.
- **Linux VPS:** the same.
- **Linux, installed by hand:** pull the new manager image and restart it.
- **Windows:** run `.\start.ps1`, which pulls the new manager image.
