## What's new in 0.53.0 — The manager watches Steam for you

Arma Reforger server releases used to be something you had to remember to look
for: open **Server files**, press *Check for updates*, and hope you did it before
your players told you the server was on an old build. The manager now does that
by itself, once a day, and tells you on the page where your servers are
([#177](https://github.com/tubalainen/reforger-server-manager/issues/177)).

Two checkboxes decide how far it is allowed to go on its own. Both are **off**
by default, so out of the box nothing downloads and nothing restarts — you just
get told.

## Do I need to do anything?

**No.** Existing installs keep working exactly as before, and the new checks
start on their own. No `.env` or compose change.

## The daily check

Once every 24 hours the manager asks Steam for the current build id of each
branch you have **installed**, and remembers it. A branch you have never
downloaded is never queried — there is no "update" for files you don't have,
only a first download.

When the build on Steam has moved past the one on your disk, a prompt appears at
the top of **Server Instances**:

> ⬆️ **New Stable server release** — build 24870635 → 24999111. Your servers keep
> running the installed build until the server files are updated.

**Update server files** starts the download right there — in the same Server
files panel at the bottom of the page, with the same progress bar and the same
streaming SteamCMD log as always. The prompt disappears by itself once the files
on disk match what Steam reported, however you updated them.

The result is remembered across a manager restart, so restarting the manager
neither loses the prompt nor re-runs the check. The **Automatic updates** card
in the Server files section shows when the last check ran and when the next one
is due, and **Check now** runs one immediately.

## Download it for me

*Download new server files automatically* lets the daily check start the
download itself for any branch that has fallen behind. It is the same job the
button starts — visible in the same place, with the same log — you simply did
not have to press anything.

Downloading is safe while servers are running: the files are updated on disk and
a running server carries on with the build it loaded at startup.

## …and put my servers on it

*Restart my servers onto the new build once it is downloaded* is the last link
in the chain, and the only one that touches a live server. When the automatic
download finishes, every instance of that branch that is meant to be running is
stopped and started again, which is what actually puts it on the new version.

**This disconnects the players on those servers**, which is why it is off by
default and why it can only be ticked once automatic downloading is on. If one
server fails to come back, the others are still restarted and the failure is in
the manager log.

Without this checkbox the files are updated and each server keeps running its
old build until you restart it yourself — from the instance card, or on its next
scheduled restart.

## Small print

- The toggles live in the manager's own database, not in `.env`, so they are set
  in the GUI and survive updates.
- The daily check runs one short `steamcmd` container per installed branch, the
  same one *Check for updates* has always used. If Docker is down, the check is
  simply skipped and tried again later.
- If Steam does not answer with a build id, that is reported as an error on the
  branch — never treated as "an update is available".
- A check that finds nothing new writes nothing and restarts nothing.
