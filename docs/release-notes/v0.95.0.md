## What's new in 0.95.0: Frozen servers, restart options, limits and scheduled backups

More from the functional review that 0.94.0 started. All of it is about a
server that runs for weeks with players on it.

### A frozen server is noticed

A server whose game loop has stopped still counts as "running": its container
is up, so neither Docker nor the crash recovery does anything, and players are
stuck. An online server prints a status line every ten seconds, so the manager
now watches for it.

- After **5 minutes** without a status line, the Servers page lists the server
  under *Needs attention* as not responding, with a **Restart** button.
- **Settings › Automation › Restart when it stops responding** restarts it by
  itself after **10 minutes**. It is off unless you switch it on.

### Daily restarts: weekdays, waiting for players, and a backup

Under **Settings › Automation**, once a daily restart time is set:

- **On these days** keeps the restart to the weekdays you choose.
- **Wait for an empty server** holds a due restart back while players are on,
  for at most 45 minutes. It restarts as soon as the last one leaves, and after
  the wait in any case.
- **Back up the saved game** takes a backup during the restart, while the
  server is stopped. A backup of a running server can catch a save half
  written; this one cannot. The newest 7 of these are kept, apart from the 10
  backups you make yourself, so a week of nightly copies does not push yours
  out. They are on the Saves tab.

Servers due at the same time now restart side by side instead of one after
another.

### Limits for a server

**Settings › Limits** gives a server a **memory limit** and a set of **CPUs**
to run on. A server that grows past its memory limit is killed (and restarted,
with *Restart after a crash* on) instead of taking the machine, and every other
server on it, down. Both take effect the next time the server starts.

### A longer, adjustable shutdown

A stopping server had 30 seconds before Docker killed it. It now has 60, and
`INSTANCE_STOP_TIMEOUT` in `.env` changes that (10 to 600 seconds). When a
stop does end in a kill, the manager log says so, since the server's last save
may not have been written.

### Smaller changes

- **Container logs are kept to 150 MB per server.** They had no limit. This
  applies to a server's container the next time it is created (any start after
  this update).
- **The Workshop being unreadable is said out loud.** The manager reads the
  Workshop website's page data, and if that fails three times in a row a
  banner says so. Until now mods just stayed at their versions without a word.
- **New templates require their mods by default**, as the game does. A server
  no longer starts without a mod it could not download unless you choose that.
  Existing templates keep their setting.
- **The Players tab says why it lists no names** when BattlEye is off in the
  template: the names come from BattlEye's lines in the log.

### How far this was checked

The Settings page and the new options were checked in a browser, and all of
the above is covered by tests. None of it has yet run on a real host with
Docker and a live server: the frozen-server detection, the limits and the
log size in particular.

## Do I need to do anything?

No. Everything new is off or unchanged until you set it, except the log size
limit, the 60-second shutdown and the default for new templates.

## Updating your setup files

One optional setting was added to `.env.example`. You only need it if you want
a shutdown time other than 60 seconds:

```
INSTANCE_STOP_TIMEOUT=60
```

No compose file or script changed. Pull the new manager image:

- **Linux with the installer (`rsm`):** `sudo rsm update --all`.
- **Linux VPS:** the same.
- **Linux, installed by hand:** pull the new manager image and restart it.
- **Windows:** run `.\start.ps1`, which pulls the new manager image.
