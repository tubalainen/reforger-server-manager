## 0.81.1: the Docker gate closes a way to replace a server image

A security fix for the Docker gate, the part of every install that stands between
the manager and Docker (v0.65.0). Found in the security review of 2026-10-20
([docs/security-review.md](https://github.com/tubalainen/reforger-server-manager/blob/main/docs/security-review.md)).

The gate allows a manager to pull only its own two images. It checked the query
of a pull request in a way that Docker reads differently. A request the gate saw
as an allowed pull could reach Docker as an image **import**: any content, stored
under the name of the game server image. Docker keeps images per machine, not per
stack. On a machine with several stacks, a manager that had been taken over could
have changed the game server image for **every** stack, and their next servers
would have started from it.

The gate now reads each such query once, refuses a parameter that is repeated, left
blank or not on its list, and sends Docker a query it wrote itself. A pull no
longer carries a body. Every pull names its tag, because a pull with no tag
downloads every tag of the image.

Two smaller gaps are closed as well. A container's network settings may carry only
aliases, not links, driver options or fixed addresses. A container may not ask for
anonymous volumes. The manager never uses either.

## Do I need to do anything?

**Update the image.** Nothing else changes: the compose files and `.env` are the
same, and so is everything the manager does.

```bash
sudo rsm update --all
```

On Windows, run the Start shortcut as usual; it pulls the new image.

## Small print

- This needed someone who could already run code inside a manager. A team admin
  using the GUI could not do it, and nothing reachable from the internet could.
- The CI job that tests the gate against a real Docker daemon now also tries both
  forms of the import and checks that the image is unchanged afterwards.
