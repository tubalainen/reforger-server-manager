## What's new in 0.94.0: Four fixes from a functional review

The manager was reviewed for things that can go wrong on a running community
server. This release fixes the four that ranked highest.

### A server that cannot start is no longer restarted for ever

A server with **Start on boot** or **Restart on crash** was brought back every
time it went down. That is right after a crash. It is wrong for a server that
cannot start at all, for example with a mod that does not compile: it came
back up every few seconds, for ever.

The manager now counts. A server that goes down **three times in a row without
ever coming online** is stopped and left stopped. The Servers page lists it
under *Needs attention* with an **Open Console** button, and the red box on the
server's page names the mod that stopped it, as before.

- A server that comes online and crashes later is still recovered every time.
- A long mod download is not a failed start, however long it takes.
- Starting the server by hand begins the count again.
- The count is kept in memory. After a manager restart the server is still
  stopped, but the *Needs attention* note is gone.

### New server builds are checked for every hour

The check for a new Arma Reforger server build ran once a day. After a game
patch, players update at once and cannot join a server on the old build, so a
server could be unjoinable for most of a day. The check now runs every hour.
A check Steam does not answer is tried again after ten minutes.

### Server files are not downloaded underneath running servers unasked

A download rewrites the folder that every running server of that branch uses.
That can crash a running server, and it stays on the old build until it is
restarted.

- **Update server files** (on the Server files page, on a server's page and in
  *Needs attention*) now names the servers running on those files and asks
  before it downloads.
- **Download new server files automatically** now waits while a server of that
  branch is running, unless **Restart my servers onto the new build** is also
  on. The Server files page says which servers it is waiting for. With the
  restart on, nothing changes: the build is downloaded and the servers are
  restarted onto it.

### The wizard keeps to the engine's limits

These values saved cleanly and then stopped the server at its config check.
The limits are the ones in Bohemia's Server Config documentation.

| Setting | Was accepted | Now |
|---|---|---|
| Max players | 1 to 256 | 1 to 128 |
| Server view distance | 500 to 12000 | 500 to 10000 |
| Admin password | anything | no spaces |
| RCON password | anything | at least 3 characters, no spaces |

A template saved with more than 128 players or more than 10000 m still opens;
the value is shown as 128 or 10000 and is written on the next save.

### How far this was checked

The wizard's limits were checked in a browser. The download question, the
waiting automatic download and the stop after three failed starts are covered
by tests, but have not yet been seen on a real host with Docker.

## Do I need to do anything?

- If you use **Download new server files automatically** without the automatic
  restart, new builds are now downloaded only while no server of that branch
  is running. Turn the restart on, or update by hand when the Servers page
  says a new build is out.
- If a template has an RCON password shorter than 3 characters, or an admin or
  RCON password with a space in it, the wizard asks you to change it the next
  time you save that template. The server refused such a password already.

## Updating your setup files

No compose file, `.env` setting or script changed. Pull the new manager image:

- **Linux with the installer (`rsm`):** `sudo rsm update --all`.
- **Linux VPS:** the same.
- **Linux, installed by hand:** pull the new manager image and restart it.
- **Windows:** run `.\start.ps1`, which pulls the new manager image.
