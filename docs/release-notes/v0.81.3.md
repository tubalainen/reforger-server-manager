## 0.81.3: the proxy is trusted by name, and a GUI with the login off answers only to its own names

Two security fixes from the security review of 2026-10-20
([docs/security-review.md](https://github.com/tubalainen/reforger-server-manager/blob/main/docs/security-review.md),
F2 and F4).

**The login throttle on a VPS could be bypassed from the machine itself (F2).** Behind
Caddy, or behind the shared edge, the manager believes the `X-Forwarded-For` header from
its proxy. That is how it knows which visitor to slow down after wrong passwords. The
compose files named the proxy by its whole network. A connection from the machine itself
into that network comes from the network's gateway, which is inside the same range. So
every program on the VPS could name its own client address and get a fresh allowance of
password guesses each time. On Linux that includes every game server of every team,
because game servers run on host networking, and so it includes the Workshop mods in
them. The compose files now name the proxy itself: `caddy`, or `rsm-edge` behind the
shared edge. The manager looks up that container's address and trusts only that address.

**A GUI with the built-in login off could be driven from a web page (F4).** With
`AUTH_ENABLED=false`, the reverse proxy in front is the only login. But a web page you
visit can point its own name at your machine (DNS rebinding) and call the GUI from your
browser, which needs no cookie when there is no login. With the login off, the GUI now
answers only to `localhost`, an IP address, `SITE_ADDRESS`, and the names you list in the
new `ALLOWED_HOSTS` setting. Turning the login off now needs `AUTH_DELEGATED_ACK=true` on
every bind, not only an exposed one. 127.0.0.1 is reachable by every program on the host
and by every game server on host networking, and none of those go through the proxy.

## Do I need to do anything?

**Yes, on a VPS. Everyone else: only if you turned the built-in login off.**

- **VPS installs** (your own Caddy, or the shared edge): refresh the compose files, as
  below. The new image works with your old compose files, but it only trusts the proxy
  by name once those files say so. Until then it logs a warning that `TRUSTED_PROXIES`
  names a whole network.
- **`AUTH_ENABLED=false`:** add `AUTH_DELEGATED_ACK=true` to `.env` if it is not there
  yet, or the manager **will not start** (also on 127.0.0.1). If your proxy reaches the
  GUI under a name other than `SITE_ADDRESS`, list that name in `ALLOWED_HOSTS`, or the
  GUI answers *400: This address is not one this manager answers to*.
- **Everyone else** (login on, local or LAN): update the image as usual. Nothing changes.

## Updating your setup files

The compose files `docker-compose.vps.yaml`, `docker-compose.vps.behind-edge.yaml` and
`docker-compose.supervisor.behind-edge.yaml` changed: `TRUSTED_PROXIES` names `caddy` or
`rsm-edge` instead of `PROXY_SUBNET`. `PROXY_SUBNET` stays in `.env`; rsm still uses it
to give each stack's proxy network a subnet of its own.

`.env.example` has one new, optional setting. It matters only with the login off:

```bash
ALLOWED_HOSTS=
```

- **Linux with the installer (`rsm`):** `sudo rsm update --all`. Accept the new compose
  files when asked and let it recreate the stack. For the Supervisor:
  `sudo rsm supervisor update`.
- **Linux, installed by hand:** download the changed compose files over yours, then
  `docker compose -f docker-compose.vps.yaml up -d` (add
  `-f docker-compose.vps.behind-edge.yaml` behind the edge).
- **Windows:** nothing to refresh; the VPS files are for Linux. Only the
  `AUTH_ENABLED=false` note above applies.

## Small print

- `TRUSTED_PROXIES` now takes container names as well as addresses and networks. A name
  is looked up when a login arrives and the answer is kept for 30 seconds. A name that
  does not resolve is trusted nowhere, so the login throttle then counts the proxy itself.
- With the login **on**, nothing about Host names changes. A page on another name gets no
  session, so there is nothing to defend.
- CI now sends a forged `X-Forwarded-For` straight from the host to the Supervisor behind
  the edge, and checks that it is not believed while the edge's still is.
