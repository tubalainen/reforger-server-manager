## What's new in 0.82.0: you decide when mods change

Closes [#246](https://github.com/tubalainen/reforger-server-manager/issues/246).

Before, a mod that follows the latest release reached the server's `config.json`
with no version, and the server took whatever it took on each start. A crash
restart in the middle of an evening could change mods under your players, and
nothing showed which version a server was running.

- **Every start keeps the mod versions already downloaded.** The manager reads
  each mod's version from the server's own files
  (`addons/<Name>_<id>/ServerData.json`) and writes it into `config.json`. This
  covers manual starts, crash recovery and the restart after a server-files
  update. Docker's own crash restarts reuse that `config.json`, so they keep the
  versions too.
- **Update mods on the daily restart** is a new switch under a server's
  Settings › Automation, next to the daily restart times. When it's on, the
  scheduled restart moves the template's mods to the newest Workshop release.
  It needs a daily restart time.
- **Settings › Mods** is a new card. It lists the template's mods with the
  version on the server and the Workshop's newest, and says when updates are
  available. It has two buttons:
  - **Force update** restarts the server now with the newest version of each
    mod, downloading only what changed. A stopped server is started, and stays
    running.
  - **Redownload and bake** stops the server, deletes the template's mods and
    what they depend on, and starts it so everything downloads again. Mods from
    templates the server used before are left alone. Use it when a download is
    broken.
- A version locked in the template never changes. A mod that isn't downloaded
  yet still downloads the newest release.

## Do I need to do anything?

Check the new switch on each server.

- **Servers that already have a daily restart** have the switch turned on by
  the update, so they keep getting new mod versions at that restart, as before.
- **Servers without a daily restart** now keep their mod versions until you
  press **Force update**, or add a restart time and turn the switch on.

## Updating your setup files

No compose file, `.env` setting or script changed. Pull the new manager image:

- **Linux with the installer (`rsm`):** `sudo rsm update --all`.
- **Linux VPS:** the same.
- **Linux, installed by hand:** pull the new manager image and restart it.
- **Windows:** run `.\start.ps1`, which pulls the new manager image.
