## What's new in 0.96.0: Kick and ban from the Players tab

The manager wrote each server's RCON settings into its `config.json` but never
used RCON itself. The only thing it could do to a live server was stop its
container: banning someone meant editing the template and restarting the
server for everyone.

It now speaks RCON to its own servers.

### On the Players tab

When the server's template has an RCON password (Settings step), each player
on the list gets two buttons:

- **Kick** disconnects them. They can join again.
- **Ban…** disconnects them and keeps them out for 1 hour, 1 day, 1 week, 30
  days or for ever, with an optional reason. The ban is made by the player's
  identity id where the log gave one, so it holds whatever name they come back
  under.

Below the list, **Ban list on the server** shows the server's own ban list, a
page at a time, and lifts a ban by its ID.

These bans are kept by the server itself. They are separate from the ban list
in the template, which every server on that template gets and which a restart
applies.

The buttons are there only when the server's RCON permission is `admin` (the
default). With `monitor`, the ban list can be read but nothing changed. Without
an RCON password, the tab says how to turn it on.

### Things to know

- **A host firewall can be in the way.** With host networking (the default on
  Linux) the manager reaches each server's RCON port on the Docker host. A
  firewall that drops traffic from Docker's networks to the host itself (ufw's
  default does) stops that. The error then says which address and port it
  tried. Allow UDP from the manager's Docker network to the RCON port range
  (`RCON_PORT_RANGE`, 19999-20018 by default). Never forward these ports from
  the internet.
- **A restart still cannot be announced in the game.** The server's RCON has no
  command that sends players a message.
- **The password and port are the ones the server was started with**, not the
  template's current ones. After changing them in the template, restart the
  server.

### How far this was checked

The RCON client was tested against a stand-in RCON server on the same machine:
login, wrong password, lost packets, replies in several parts and messages the
server sends on its own. The commands are the ones in Bohemia's Server
Management documentation. It has not yet been used against a real Arma
Reforger server.

## Do I need to do anything?

No. To use kick and ban, give the server's template an RCON password and
restart the server.

## Updating your setup files

No compose file, `.env` setting or script changed. Pull the new manager image:

- **Linux with the installer (`rsm`):** `sudo rsm update --all`.
- **Linux VPS:** the same.
- **Linux, installed by hand:** pull the new manager image and restart it.
- **Windows:** run `.\start.ps1`, which pulls the new manager image.
