## What's new in 0.91.0: Required or optional, per mod

### Set each mod to Required or Optional

Each mod on a template's **Mods** step now has a Required / Optional picker
next to its version. It writes the mod's own `required` flag in config.json:

- **Required:** the server won't start if the mod can't be downloaded from the
  Workshop.
- **Optional:** the server drops the mod with a warning in its log and starts
  anyway.
- **Default:** follows *Mods required by default* under Settings › Advanced
  settings, and writes nothing for the mod, as before.

A template that sets no mod to Required or Optional writes the same
config.json as before.

### Fixed: a hand-typed `"required"` froze the mod list

Before this release, adding `"required": false` (or any key the manager
didn't know) to a mod with **Edit JSON** saved the whole mod list as a
hand-edited override. From then on that override replaced the Mods step's
list on every save. Mods you added, removed or changed on the Mods step
afterwards never reached config.json, and nothing said so.

The mod list can no longer become an override. A template already caught by
this is released when it opens: the Mods step shows its own list, keeps any
`required` you had typed, and the next save writes that list.

**If one of your templates was affected,** the next save writes the list you
see on the Mods step, which can differ from what the server has been running.
Look over the Mods step before you save.

## Do I need to do anything?

No, unless you had hand-typed `"required"` on a mod. In that case, check the
template's Mods step before its next save.

## Updating your setup files

No compose file, `.env` setting or script changed. Pull the new manager image:

- **Linux with the installer (`rsm`):** `sudo rsm update --all`.
- **Linux VPS:** the same.
- **Linux, installed by hand:** pull the new manager image and restart it.
- **Windows:** run `.\start.ps1`, which pulls the new manager image.
