## What's new in 0.45.3 — stop recreating the container on every start

Fixes a bug introduced by the host-networking change in v0.45.2. **Update if you
are on v0.45.2.**

## Do I need to do anything?

Just update. No restart dance this time — the next start of each server picks
this up on its own.

---

## What went wrong

v0.45.2 moved game servers to host networking, where Docker publishes no ports
because the server binds the host's ports directly. But the existing
"have the published ports drifted?" check still compared the container's
(correctly empty) port bindings against the three ports it expected, decided they
did not match, and **recreated the container on every single start**.

Two consequences:

- Every start needlessly destroyed and rebuilt the container. Nothing was lost —
  all state lives in bind mounts — but it wasted time and threw away the
  container's log history each time.
- It fired *before* the network-mode check, so the log line always read
  `published ports changed` instead of
  `network mode changed (host vs bridge, #150)`. Anyone following the v0.45.2
  notes and looking for that message would never have seen it.

The v0.45.2 fix itself worked — servers did end up on host networking. This just
makes them stay there quietly.

## The fix

The published-ports check now understands host networking: with no NAT there are
no bindings to compare, so an empty set is correct rather than drift. Bridge mode
(Docker Desktop) is unchanged and still detects genuinely stale mappings.

## While we are here — what host networking covers

Since it came up: the change applies to **every** server instance and **all** of
its ports. With host networking the server binds its own game, A2S and RCON ports
straight onto the host, so nothing about game traffic passes through a proxy or
NAT. Per-instance port leases already guaranteed each server a unique set, which
is what keeps multiple servers apart when they share the host's network
namespace.

Firewall rules are unchanged: UDP `2001-2020` and `17777-17796`. Keep RCON
(`19999-20018`) closed unless you use it remotely — under host networking it
binds directly on the host, exactly as it was published before.
