## What's new in 0.46.0 — admins, whitelist and ban list

Server templates can now name who administers a server and who is allowed to join
it ([#154](https://github.com/tubalainen/reforger-server-manager/issues/154)).

## Do I need to do anything?

**No.** Nothing changes for a template that doesn't use the new lists — see
[Is this safe to update to?](#is-this-safe) below for why that is guaranteed
rather than merely likely.

---

## Player access, on the template's Settings step

A new **Player access** section holds three lists. They belong to the template, so
every server instance built from it gets the same ones, and every change is
recorded in that template's change log.

### Server admins

The people who run the server. A listed admin can `#login` **without** the admin
password and uses the priority join queue.

- Takes a **Steam64 id** (17 digits) or a **Bohemia identity id**.
- Paste a whole batch at once — one per line, or separated by commas or spaces.
- Each id is checked as you type. Anything that isn't an id is reported by name and
  left in the box so you can fix it, instead of the whole paste failing.
- The game applies at most **20** admins; the wizard counts them and warns you
  before the list stops working.

### Whitelist

- **Empty (the default): everyone may join.** Nothing is written to `config.json`.
- Add **one** player and the server becomes whitelist-only — everyone not on the
  list is refused. The wizard says so in bold when the list is non-empty, because
  the easy mistake here is locking yourself out of your own server.

### Ban list

Players refused entry, with an optional reason recorded next to each. Bans listed
here apply from the moment the server starts; to remove someone mid-session, use
the in-game admin tools or RCON as before.

### Steam id or identity id?

They are not interchangeable, and this is the mistake that quietly costs an admin
their rights:

| List | Accepts |
|---|---|
| Server admins | Steam64 **or** Bohemia identity id |
| Whitelist, Ban list | Bohemia identity id **only** |

The wizard enforces this — a Steam id typed into the whitelist is refused with an
explanation rather than silently saved as an entry that never matches. You can find
a player's identity id in the Arma Reforger launcher, in their Bohemia account
profile, or in the server log when they connect.

## <a id="is-this-safe"></a>Is this safe to update to?

Yes — and deliberately so. The whitelist and ban list are written into
`config.json` **only when they hold at least one player**. A template that doesn't
use them renders exactly the config it rendered in v0.45.3, byte for byte, so a
server that doesn't use the feature cannot be affected by it. Emptying a list
removes the key again.

That containment is doing real work here. The `game.playerWhitelist` and
`game.playerBanList` fields are documented by server hosts rather than by Bohemia,
and we could not verify them against the engine's own schema before shipping. If it
turns out your server ignores these lists — or refuses to start once one is set —
remove the entries and
[tell us on #154](https://github.com/tubalainen/reforger-server-manager/issues/154):
that is the signal to move the ban list onto RCON instead. The **admins** list is
not affected by any of this; `game.admins` is long-established.

## Also in this release

- The change log gets proper lines for all three lists — *"Added server admin …"*,
  *"Whitelisted 'Ann' (…)"*, *"Banned 'Bob' (…)"*, *"Unbanned …"* and ban-reason
  edits — instead of an unreadable raw array diff. Searching a player's name or id
  now finds every time they were banned, unbanned or whitelisted.
- Copying a template carries its access lists, and the copy's change log records
  who it started with.
- Hand-written lists survive the wizard: a `playerWhitelist` or `playerBanList`
  added through **Edit JSON** or an uploaded `config.json` is read back into the
  GUI instead of being flagged as a custom key.

**Upgrade:** the manager updates itself on start, or pull
`ghcr.io/tubalainen/reforger-server-manager:latest`.
