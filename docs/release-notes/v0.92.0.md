## What's new in 0.92.0: See which mod stopped a server

### A red box names the mods that stopped the last start

After a Reforger update, mods often stop loading and the server won't start.
The reason is in the server's console.log, buried among other lines. When a
server's last start failed because of a mod, a red box on top of the server's
page now says which mod failed and why:

- **A missing dependency.** For example, *WCS_Scopes needs WCS_NATO and
  WCS_RU, which aren't installed*. The box lists every dependency the mod's
  project file names that isn't on disk, not only the first one the engine
  stopped at. Each one links to its Workshop page.
- **Knock-on failures.** A mod that fails only because a mod it needs failed
  is marked *knock-on*: fix the other one first.
- **Scripts that don't compile.** The compile errors are shown as the log
  prints them. The log doesn't say which mod they come from, so the box
  doesn't guess.

**Remove in template…** opens the server's template on the Mods step with the
failing mods marked *failed*. A failed mod that is in the template only
because other mods require it has no ✕: it goes when they do, so those mods
are marked *needs a failed mod*. A Prod template has to be copied to Test
first, as before. Under Settings › Mods, the same mods carry a red badge.

Only a start that **failed** counts. A mod that logs errors on a server that
still comes online is not flagged, because that server is playable.

### Fixed: a mod whose project file isn't called addon.gproj

Some mods ship their project file under their own name, for example
`TFMattockWeapons.gproj`. Their dependencies were not read, so **Redownload
and bake** left those dependencies on disk. They are read now.

## Do I need to do anything?

No.

## Updating your setup files

No compose file, `.env` setting or script changed. Pull the new manager image:

- **Linux with the installer (`rsm`):** `sudo rsm update --all`.
- **Linux VPS:** the same.
- **Linux, installed by hand:** pull the new manager image and restart it.
- **Windows:** run `.\start.ps1`, which pulls the new manager image.
