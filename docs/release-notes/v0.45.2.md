## What's new in 0.45.2 — game traffic no longer goes through Docker's proxy

Follow-up to [#150](https://github.com/tubalainen/reforger-server-manager/issues/150).
v0.45.1 removed one suspect; this removes the actual proxy from the path.

## Do I need to do anything?

| If you… | Then |
|---|---|
| Run servers on **Linux** | Update, then **restart each server once** so it is rebuilt on host networking |
| Run on **Windows / Docker Desktop** | Nothing changes — Docker Desktop has no real host networking, so publishing stays as it was |

---

## What changed

Game servers now use **host networking** instead of Docker's NAT'd bridge.

Under bridge networking every published UDP port sat behind Docker's userland
**`docker-proxy`**:

```
UNCONN  0.0.0.0:2001   users:(("docker-proxy",pid=8061,fd=8))
UNCONN  0.0.0.0:17777  users:(("docker-proxy",pid=8082,fd=8))
```

That proxy rewrites the source address of inbound packets to the bridge gateway,
so the Arma server saw **every player arriving from `172.x.0.1`** rather than
from their real address. Game networking and BattlEye both depend on the real
client address, and connections fail.

**Game and A2S traffic must never be proxied.** With host networking the server
binds its own UDP ports directly on the host — no NAT, no `docker-proxy`, no
address rewriting. This is how game servers are normally run under Docker.

The web GUI is unaffected: it is still the only thing behind a reverse proxy,
which is exactly where a proxy belongs.

### Existing servers are rebuilt automatically

Docker fixes a container's network mode at creation, so a server built under
bridge networking would keep its proxied ports for ever. The manager now detects
that and recreates the container **on the next start** — stop and start each
server once (or press **Restart**) after updating. Look for:

```
Recreating container for <name>: network mode changed (host vs bridge, #150)
```

Confirm it took — the proxy should be gone from your ports:

```bash
ss -ulnp | grep -E ':(2001|17777)'
```

You want the Arma server process itself, **not** `docker-proxy`.

### If you need the old behaviour

```
INSTANCE_NETWORK_MODE=bridge
```

`auto` (the default) uses host networking everywhere except Docker Desktop,
which cannot provide it.

## Note on ports

With host networking the container shares the host's network namespace, so the
per-instance port leases are what keep multiple servers apart — they already
were unique per instance, so nothing changes there. Your firewall rules stay the
same: UDP `2001-2020` and `17777-17796`.
